Kritik bulgu 1

B1 · Sözcüksüz metin tüm indeksi kırıyor

Belirti

HashEmbedder metindeki sözcükleri (\w+) hash'liyor. Sözcük içermeyen bir metin — örneğin yalnızca noktalama/sembol, "!!!" veya "---" — için vektör tamamen sıfır çıkıyor. validate_vector sıfır normu güvenli hata saydığı için tek bir kayıt tüm kapsamın index_scope'unu düşürüyor. Aynı şekilde "???" gibi sözcüksüz bir sorgu retrieve'i hata ile bitiriyor; oysa eşleşecek bir şey olmadığı için boş liste dönmeli.

Kanıt (düzeltme öncesi)

E1 index_scope ERROR -> invalid_vector   # tek "!!!" kaydı tüm kapsamı kırdı
E2 query '???': ERROR -> invalid_vector
E2 query '!!':  ERROR -> invalid_vector
E2 query '---': ERROR -> invalid_vector

Kök neden

Önce

def embed(self, text):
    vector = [0.0] * self.dimension
    for token in sorted(tokens(text)):
        digest = sha256(token.encode()).digest()
        vector[int.from_bytes(digest[:4], "big") % self.dimension] += 1.0
    return vector

Sonra

def embed(self, text):
    vector = [0.0] * self.dimension
    words = sorted(tokens(text))
    if not words:
        # Sembol-only metin: ham metinden deterministik
        # sıfır-olmayan vektör üret.
        digest = sha256(
            unicodedata.normalize("NFC", text).encode()
        ).digest()
        vector[int.from_bytes(digest[:4], "big") % self.dimension] += 1.0
        return vector
    for token in words:
        digest = sha256(token.encode()).digest()
        vector[int.from_bytes(digest[:4], "big") % self.dimension] += 1.0
    return vector
Tasarım notu: Sıfır vektör kuralı korunuyor (validate_vector hâlâ geçersiz vektörü reddeder). Düzeltme yalnızca geçerli girdinin sıfır vektör üretmesini engelliyor. Sözcük içeren metinlerin vektörleri bit düzeyinde aynı kaldığı için mevcut indeksler için yeniden indeksleme gerekmez.

B2 · Sürüm geçmişi kaydı kalıcı olarak kilitleyebiliyor

Belirti

Her yazma versions tablosuna tam payload'ın bir kopyasını ekler. Byte kotası ölçüsü max(live_bytes, history_bytes) olduğundan pratikte kümülatif yazma bütçesi hâline gelir: her güncelleme kalıcı yer tüketir. allow_eviction=True olsa bile tahliye yalnızca bütün kayıtları sildiği için korumalı kaydın kendi sürümleri geri kazanılmaz; kayıt bir kez eşiği aşınca sonsuza dek quota_exceeded verir.

Kanıt (düzeltme öncesi)

# Policy(max_bytes_per_tier=1200, allow_eviction=True), 200 karakterlik kayıt
E3 update failed at version 1 -> quota_exceeded
E3 successful updates before failure: 0
E3 versions stored: 1 bytes: 667

Kök neden ve düzeltme

Sürüm payload'ları yedek geçmiştir: canlı kayıt memories.payload'da durur. Bu yüzden kota aşımında en eski sürüm satırlarını geri kazanmak hiçbir canlı veriyi kaybetmez. Kota kontrolü, kayıt tahliyesinden önce bu en ucuz alanı geri kazanacak şekilde genişletildi.

if not over():
    return
if self.policy.allow_eviction:
    self._prune_history(db, scope, tier)   # <-- eklendi
    if not over():
        return
    victims = db.execute(...)

def _prune_history(self, db, scope, tier):
    # Sürüm payload'ları yedek geçmiştir; canlı kayıt memories.payload'da kalır.
    # Bu olmadan sık güncellenen tek kayıt kendi sürümleri yüzünden kilitlenir.
    args = (scope.tenant_id, scope.user_id, tier)
    total = ("SELECT coalesce(sum(length(CAST(v.payload AS BLOB))),0) "
             "FROM versions v JOIN memories m ON m.id=v.memory_id "
             "WHERE m.tenant_id=? AND m.user_id=? AND m.tier=?")
    while db.execute(total, args).fetchone()[0] > self.policy.max_bytes_per_tier:
        removed = db.execute(
            "DELETE FROM versions WHERE rowid IN (SELECT v.rowid FROM versions v "
            "JOIN memories m ON m.id=v.memory_id "
            "WHERE m.tenant_id=? AND m.user_id=? AND m.tier=? "
            "ORDER BY v.rowid LIMIT 100)", args).rowcount
        if not removed:
            return
Bilinçli karar: Geri kazanım yalnızca allow_eviction=True iken çalışır. Varsayılan politikada otomatik silme kapalıdır; bu durumda şartnamenin istediği gibi açık quota_exceeded hatası döner. README bu davranışı belgeleyecek şekilde güncellendi.

Kritik bulgu 3

B3 · Kimliksiz çağıran arama kotasını tüketiyor

Belirti

Body/gövde sınırlarını ve hızı uygulayan ASGI middleware, kimlik doğrulama FastAPI bağımlılığından önce çalışır. Bu yüzden arama penceresi tek bir global sayaçla tutulduğunda, geçerli token'ı olmayan bir çağıran 120 istek/dakika ile herkesin arama kotasını yakabiliyor. Deney: 401 dönen istek kotayı yiyor, ardından geçerli token 429 alıyor.

Kanıt (düzeltme öncesi)

E5 unauthenticated search status: 401 -> then authenticated: 429 search_rate_limit

Düzeltme

Arama penceresi artık bearer kimliğinin hash'i (yoksa istemci konağı) başına ayrı tutuluyor. Middleware kimliği doğrulayamasa da, çağıranları birbirinden ayırabilir; böylece bir token grubu diğerinin kotasını tüketemez. Ham token saklanmaz; yalnızca sha256 özeti anahtar olur.

Önce

# __init__
self.search_count = 0
self.window_start = time.monotonic()

# arama
if scope["path"] == "/v1/memories/search":
    if now - self.window_start >= 60:
        self.window_start, self.search_count = now, 0
    if self.search_count >= self.limits.searches_per_minute:
        return await fail("search_rate_limit", 429)
    self.search_count += 1

Sonra

def _search_window_key(scope):
    headers = {k.lower(): v for k, v in scope.get("headers", [])}
    auth = headers.get(b"authorization")
    if auth:
        return "bearer:" + sha256(auth).hexdigest()
    client = scope.get("client")
    return "host:" + (client[0] if client else "unknown")

# arama
key = _search_window_key(scope)
window_start, count = self.search_windows.get(key, (now, 0))
if now - window_start >= 60:
    window_start, count = now, 0
if count >= self.limits.searches_per_minute:
    return await fail("search_rate_limit", 429)
self.search_windows[key] = (window_start, count + 1)

B4 · Döngü hatası artık source_cycle döndürüyor

_link_sources içindeki açık döngü kontrolü pratikte erişilemezdi: yeni kaydın uuid'si hiçbir bağımlılıkta olamaz ve update yolunda kaydın tüm türevleri _link_sources'tan önce silinirdi. Bu yüzden gerçek bir döngü denemesi source_cycle yerine not_found döndürüyordu. Düzeltme: türevler silinmeden önce atalık kontrolü yapılıp source_cycle yükseltiliyor.

E4 (önce)  cycle via update -> not_found
E4 (sonra) cycle via update -> source_cycle    # A ve B yerinde kalıyor

B5 · Aday sınırı artık kesiyor, arama düşmüyor

candidates daha önce LIMIT max_candidates+1 çekip len(rows) <= max_candidates bekler, aşımda aramayı hata ile bitirirdi. Düzeltme: sonuçlar max_candidates ile sınırlanır (deterministik id sırası), dolu bir kapsam aranabilir kalır. Not: sıralama id tabanlıdır; ilgililik sıralaması retrieval aşamasında yapılır.

B6 · Middleware istisnayı sessizce yutuyor

except Exception bloğu hata metnini loglamıyor (doğru: içerik/secret sızabilir) ama istisna sınıfını bile loglamıyor. Yanıt başlamışsa hata yanıtı da gönderilmeyip yanıt sessizce kesiliyor. Öneri: yalnızca sınıf adını (içerik olmadan) loglamak.

B7 · hybrid_fake anlatısı

Evaluation verisi hash embedder'ın ilgisiz sorgularda lexical'den daha kötü olduğunu gösteriyor (unrelated_false_recall 0.6667 vs 0.0000). README bunu kısmen söylüyor (“yanlış pozitif üretmiştir”); anlatı ve varsayılan (lexical) doğru. Kalite artışı olarak sunulmamalı — sunulmuyor.

B8 · Kardeş projeye sabit test bağlılığı

pyproject.toml içindeki pythonpath = ["src", "../dynamic-context-assembler/src"] nedeniyle testler yalnızca kardeş depo yanındayken çalışır. Çekirdek sıfır çalışma-zamanı bağımlılığını koruyor; yalnızca test takımı Assembler'a bağlı. Şartname gerçek sözleşmeyle entegrasyonu istediği için bu bilinçli bir tercih.
